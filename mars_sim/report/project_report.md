## 一、题目要求

编写命令行程序 `mars_sim`，读取基地初始状态（base.txt）、事件序列（events.txt）和行动序列
（actions.txt）三个文件，按固定的时间片规则推进仿真，把结果写入 `--output` 指定的文件。

核心约束：

- 程序名与参数固定：`./mars_sim --base FILE --events FILE --actions FILE --output FILE`。
- 正常运行时结果只写入 `--output` 文件，恰好 12 行，顺序、字段名和大小写不能变。
- 非法输入返回非零状态，不崩溃，并且仍然要输出 `RESULT ERROR` / `REASON 具体原因` 两行结果文件；
  其中「行动数量 M 不等于事件数量 N」必须返回 2。
- 源码必须能在 GCC/Linux 下用 `gcc -std=c11 -Wall -Wextra -pedantic -O2` 重新编译（-Wall -Wextra
  -pedantic 下无警告），Makefile 与讲义一致。

## 二、总体设计

程序按「一份状态 + 三个输入解析 + 一份输出」划分模块，各模块职责单一、互不越界。

| 模块 | 职责 |
| --- | --- |
| main.c | 解析命令行参数；按时间片驱动「事件 → 行动 → 结算 → 判定」；统一处理错误返回与错误结果文件 |
| state.c / state.h | 定义 BaseState（六个初始字段）与 SimState（含 ACTIVE_ROBOT、LAB_ON、三类故障、REPAIRED、FAILED_ACTION、TIME）；读取并校验 base.txt；时间片结算 settle_tick |
| event.c / event.h | 读取 events.txt：数量行、事件名、1～3 组「资源名 整数变化量」，逐项检查合法性 |
| action.c / action.h | 应用事件资源变化并激活故障；执行行动并维护 REPAIRED / FAILED_ACTION；读取并校验 actions.txt |
| report.c / report.h | 写出正常结果（12 行）与错误结果（`RESULT ERROR` / `REASON ...`） |
| sim_util.c / sim_util.h | 公共小工具：数量行解析、空白行判断、错误原因格式化 |

状态集中在一个 `SimState` 结构体中，资源初始值来自 `BaseState`，其余字段在 main 中按讲义要求初始化
（ACTIVE_ROBOT = 0、LAB_ON = 1、故障集合为空、REPAIRED = 0、FAILED_ACTION = 0、TIME = 0）。

## 三、关键实现

### 1. 时间片执行顺序

每个时间片严格按讲义第四节的六步执行，不调换顺序：

1. 应用本时间片事件的资源变化量，故障事件同时置位对应故障标志；
2. 检查条件并执行本时间片行动，行动失败只把 FAILED_ACTION 加 1，不改变已经发生的事件效果；
3. 结算：`LAB_ON = 1` 时 OXYGEN 减 2、WATER 减 1，`LAB_ON = 0` 时 OXYGEN 减 1、WATER 不变；
4. 把 POWER / OXYGEN / WATER 限制到不小于 0，HULL 限制在 0～100，TEMPERATURE 不截断；
5. 当前时间加 1，然后检查失败条件；
6. 失败则停止后续时间片（结果文件在仿真结束后统一写出，因此中途不会产生半截文件）。

由于结算发生在第 3 步、判定发生在第 5 步，「SHUTDOWN LAB 从本时间片结算开始生效」和「TIME 记为
发生失败的时间片编号」都自然成立。

### 2. 输入解析与非法输入

三个文件都遵守讲义第三节的格式约定：字段之间是一个或多个空格，空行不计入记录。

- base.txt：必须恰好出现 POWER / OXYGEN / WATER / TEMPERATURE / HULL / ROBOT 六个字段，字段不能
  重复、不能缺失，每行只能有「字段名 整数」两个词；数值范围按讲义逐字段检查。
- events.txt：第一行是数量 N（1～72），随后每条记录是事件名加 1～3 组「资源名 整数」；未知事件名、
  未知资源名、变化量不是整数、字段成对缺失、一行超过 3 组都判为非法。
- actions.txt：第一行是数量 M（1～72），每行是「行动名」或「行动名 目标」；只有题目给出的五种行动
  及其合法目标组合可以通过。

解析中发现的任何问题都会记录一条中文原因（例如「数值范围错误 POWER -100」「未知事件名 METEOR
（第 2 行）」），由 main 统一写出到 `--output`，并返回非零状态。这样既满足「不产生可作为正确结果
的半截文件」，也满足「异常时仍要输出 result.txt」。

### 3. 退出码约定

- 正常仿真结束（SURVIVED 或 FAILED）：返回 0；
- 行动数量 M 与事件数量 N 不一致：返回 2；
- 其余非法输入（文件打不开、格式错误、字段越界、未知名称等）：返回 1；
- 命令行参数错误：返回 1。

### 4. 结果文件

正常结果按讲义第五节写出 12 行，得分公式为
`SCORE = TIME + 10 × REPAIRED - 5 × FAILED_ACTION + POWER/10 + OXYGEN/10 + WATER/10 + HULL/10`，
使用 C 语言整数除法，结果为负时输出 0。

错误结果只写两行：`RESULT ERROR` 和 `REASON 具体原因`，与讲义第二节给出的示例一致。

## 四、测试与验证

公开测试位于 `tests/`，入口是 `bash tests/run_tests.sh`，它会编译主程序与全部单元测试并做端到端比较。

单元测试覆盖：

| 测试 | 内容 |
| --- | --- |
| tests/test_apply_event.c | 事件资源变化与 SOLAR 故障激活 |
| tests/test_action.c | 启动机器人、修复 SOLAR / COMMUNICATION、关闭实验舱、重复启动应失败 |
| tests/test_settle.c | 实验舱开启/关闭时的消耗差异、氧气耗尽触发失败 |
| tests/test_load_actions.c | actions.txt 的读取结果 |

端到端测试使用讲义第 6 节给出的四个文件，结果与 `tests/expected.txt` 逐行比较，必须完全一致
（实际输出为 RESULT SURVIVED、TIME 4、POWER 45、OXYGEN 47、WATER 56、TEMPERATURE 14、HULL 85、
ROBOT 1、ACTIVE_ROBOT 1、REPAIRED 1、FAILED_ACTION 0、SCORE 35）。

额外的错误处理用例（均已手工验证）：

| 输入 | 期望行为 |
| --- | --- |
| POWER -100 | 返回 1，结果文件为 `RESULT ERROR` / `REASON 数值范围错误 POWER -100` |
| 缺少、重复或未知 base 字段 | 返回 1，并给出对应原因 |
| 未知事件名、未知资源名、变化量非整数 | 返回 1，并指出所在行号 |
| 一行超过 3 组资源变化、字段成对缺失 | 返回 1 |
| 事件数量非法（0、超过 72、数量行有多余内容） | 返回 1 |
| 行动名或目标非法 | 返回 1 |
| 行动数量 M 与事件数量 N 不一致 | 返回 2，并写出 `RESULT ERROR` |
| base 文件或 actions 文件不存在 | 返回 1，并写出 `RESULT ERROR` |
| OXYGEN 提前耗尽 | 正常写出 12 行结果，RESULT 为 FAILED，TIME 为失败的时间片编号 |

编译验证：`gcc -std=c11 -Wall -Wextra -pedantic -O2` 下主程序与四个单元测试均无警告；程序在不同
参数顺序下都能正确运行。

## 五、遇到的问题与处理

1. 空行的处理。最初按行号顺序读取记录，文件中间或末尾多一个空行就会被判为格式错误；讲义明确
   「空行不计入记录」，因此三个读取函数都改为先跳过纯空白行再计入记录，修正后带空行的输入文件
   仍能得到与标准答案一致的结果。
2. 异常时缺少结果文件。最初只在终端打印错误并返回非零状态，没有写出 `--output` 文件，不符合
   讲义第二节「异常时也要输出 result.txt」的要求。现在所有错误路径都会写出两行错误结果，且先
   从命令行中定位 `--output`，保证参数本身出错时也能写出文件。
3. 退出码。数量不一致的情况原先返回 1，讲义要求返回 2，已在 main 中单独区分。
4. 错误信息需要在终端和文件两处使用，且必须单行显示，因此统一用 `sim_util` 中的原因缓冲区保存
   格式化后的中文原因，避免出现多余换行破坏结果文件的行结构。

## 六、可以继续改进的地方

- 三个读取函数中「跳过空行后取下一行」的逻辑有重复，可以再抽成一个公共的读行函数。
- 事件名、资源名、行动名目前写死在各自的校验函数里，可以集中到一张表，便于以后扩展。
- 终端提示目前只有错误信息，如需观察过程可以增加可选的调试输出（但绝不能写入结果文件）。
